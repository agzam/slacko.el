Search for, and read Slack messages in Emacs, viewing them in org-mode outline.

[[file:./test/preview.gif]]

Status: fresh out of oven - very experimental, expect weirdness!

* Why?

Slack's interface makes it frustratingly difficult to quickly find and extract plain text from messages. Want to grab a code snippet someone shared three weeks ago? Good luck copying it cleanly from the Slack UI. Need to search through old conversations and collect information? You'll be clicking through endless threads and fighting with Slack's formatting.

This package solves that problem by bringing Slack search into Emacs, where you can:
- Search messages like you search anything else in Emacs
- Get results as nicely formatted org-mode documents
- Click links to jump directly to messages in the Slack app
- Copy text without wrestling with Slack's UI quirks

* What?

~slacko~ lets you search Slack messages and displays results in an org-mode buffer. Each result includes:

- Clickable author names, channel names, and timestamps
- Message content with proper formatting:
  - Code blocks converted to org src blocks
  - Inline code preserved as org verbatim
  - Links converted to org link format
  - Bold/italic formatting maintained

The package automatically handles:
- Different conversation types (channels, DMs, group DMs, private channels)
- Slack's custom mrkdwn format conversion to org-mode
- Reactions, which Slack leaves out of search results and only hands over one request per message: they are fetched for what the window shows plus a few screenfuls below it, so results appear at once and reactions catch up as you scroll

* How?

** Getting Slack credentials

Slack doesn't make it easy to search via API without explicit API access and going through their OAuth dance. But why would that ever stop you - fearless Emacs warrior for software freedom?

You need two things:
1. Your Slack web session token (starts with ~xoxc-~)
2. Your ~d~ cookie value - (starts with ~xoxd-~)
   
You can get them from authenticated Slack instance in the web app.
Once you have them, you can store them in an encrypted ~netrc~ format file like this, 

#+begin_src
machine MYORG.slack.com login token password xoxd-your-token-here
machine MYORG.slack.com login cookie password d-cookie-value-here
#+end_src

or put them in an env var, or plain text file - stick them wherever you like, I'm not your uncle - I won't judge.

For easy way to get these two, I wrote this automation script [[https://github.com/agzam/lazy-token-catcher][lazy-token-catcher]].

*** But wait, perhaps we don't have to do any of that crap

I did some investigation and dig into how Slack App stores your credentials (I only did this for Mac) and figured a way of extracting token automatically. It should prompt to access the keychain though, don't freak out. 
Linux way coming soon.

** Configuration

You need to tell ~slacko~ how to access session token and 'd-cookie', they set in ~slacko-token-function~ and ~slacko-cookie-function~

Here's how you can grab them from a given netrc-format encrypted file:

#+begin_src emacs-lisp
(defun slacko-creds-fn (kind)
  (let ((auth-sources `(,(expand-file-name "~/.doom.d/.secrets.gpg"))))
    (auth-source-pick-first-password :host "MYORG.slack.com" :user kind)))

(setq slacko-token-function
      (lambda () (slacko-creds-fn "token")))

(setq slacko-cookie-function
      (lambda () (slacko-creds-fn "cookie")))
#+end_src

** Multiple Slack workspaces

All workspaces you're signed into in the Slack desktop app are automatically discovered and stored in the credentials file. By default, ~slacko-search~ uses ~slacko-default-host~ or the first workspace found.

To choose a specific workspace, invoke with a prefix argument:

#+begin_src
C-u M-x slacko-search
#+end_src

This prompts you to pick from available workspaces before entering the search query. If only one workspace exists, it's selected automatically.

You can also set a preferred default:

#+begin_src emacs-lisp
(setq slacko-default-host "myteam.slack.com")
#+end_src

** Usage

Once token and cookie retrieval configured, just run:

#+begin_src emacs-lisp
M-x slacko-search
#+end_src

I'm in the process of adding more functionality, I just added a way for displaying messages and threads.

** Searching with Consult

With [[https://github.com/minad/consult][Consult]] installed, ~slacko-search~ runs the search as a Consult session: results arrive while you type, one candidate per message showing who said it, where, when and what it says. Without Consult the command works exactly as before - Consult is not a dependency of this package, and nothing here installs it.

Inside the session:

- =RET= opens the thread the message belongs to, in a ~slacko-thread-mode~ buffer named after the conversation - =*Slack Thread: #releases*=, =*Slack Thread: @natalie.see*=.  Each thread gets its own buffer, so you can pick several out of one search; opening the same one again refreshes it where it is
- your ~consult-preview-key~ renders the candidate under point in a ~slacko-search-mode~ buffer, without asking Slack for anything
- the whole input goes to Slack, so its search operators work: ~in:#channel~, ~from:@someone~, ~before:2026-01-01~
- =#query#filter= narrows the results already fetched, Consult's usual splitting syntax, matching the full text of a message and not only the part shown on the line
- =C-u M-x slacko-search= asks which workspace to search first

Slack returns at most 100 messages per request, and the session follows up to ~slacko-consult-max-pages~ of them:

#+begin_src emacs-lisp
(setq slacko-consult-max-pages 3)     ; pages fetched per query
(setq slacko-consult-page-size 100)   ; messages per page, 100 is Slack's cap
(setq slacko-consult-text-lines 2)    ; message lines under a candidate, 0 for none
(setq slacko-consult-text-width 110)  ; width those lines are filled to
#+end_src

*** Embark actions

With [[https://github.com/oantolin/embark][Embark]] installed, ~embark-act~ on a result offers:

| =RET= | open the thread                                   |
| =o=   | show the message in a ~slacko-search-mode~ buffer |
| =s=   | open the message in the Slack app                 |
| =w=   | copy the message link                             |
| =W=   | copy the message text                             |

~embark-export~ renders every result of the session into a ~slacko-search-mode~ buffer, the same org outline the plain ~slacko-search~ produces.

** Reactions

Slack's search API does not return reactions, and fetching them costs one request per message. They are filled in behind your reading instead: whatever the window shows plus ~slacko-reactions-lookahead~ screenfuls below it gets asked for, at most ~slacko-reactions-max-requests~ at a time.

#+begin_src emacs-lisp
(setq slacko-reactions-lookahead 2)     ; screenfuls fetched ahead of the scrolling
(setq slacko-reactions-max-requests 6)  ; requests in flight at once
#+end_src

** Optional: Customize browser tab behavior

Slack notoriously (and quite stupidly) doesn't allow deep-linking directly to a given message - only channels and threads. In practice, this means whenever you click a Slack permalink outside of the app, it first opens it in the browser, only then navigates to the app, leaving useless "you can close this now" tab, which can be quite annoying.

On mac, the package automatically closes that useless redirect tab. If you want to disable that:

#+begin_src emacs-lisp
(setq slacko-inhibit-redirect-browser-tab nil)
#+end_src

You can also customize which browser it targets and the delay before closing the tab:

#+begin_src emacs-lisp
(setq slacko-browser-name "Google Chrome")  ; or "Safari", etc.
(setq slacko-close-tab-delay 2.0)           ; seconds
#+end_src
