#+TITLE: Changelog
#+AUTHOR: Ag Ibragimov

All notable changes to this project will be documented in this file.

* [1.4.0] - 2026-09-22
** Added
- Consult session for searching: with ~consult~ installed, ~slacko-search~ runs the search in the minibuffer, results arriving while the query is typed.  Candidates carry the message itself, so the preview and every action work off what the search already returned
- ~RET~ on a result opens its thread; the candidate under point renders in a ~slacko-search-mode~ buffer when ~consult-preview-key~ says so, without a single request
- Embark actions for a result - open the thread, show the message in a ~slacko-search-mode~ buffer, open it in the Slack app, copy its link, copy its text - and ~embark-export~ rendering the whole result set into the org outline ~slacko-search~ has always produced
- Direct messages are labelled with the name of the person they are with, and group ones with their members, instead of the user id Slack names those conversations after.  A message the other party wrote names the conversation for free; the rest cost one ~users.info~ request per person per session
- ~slacko-reactions.el~: reactions are fetched for what the window shows plus a lookahead, a few requests at a time, rather than one blocking request per message before anything appears
- ~slacko-creds-api-request-async~ alongside the synchronous request function

** Changed
- A captured thread is titled and its buffer named after the conversation it came from - ~*Slack Thread: #releases*~, ~*Slack Thread: @natalie.see*~ - instead of the bare ~Slack Thread~.  Opening one from a search result costs nothing extra: the result already describes its conversation
- Every thread gets a buffer of its own, so several picked out of one set of search results stay open side by side.  A thread opened again is refreshed where it is rather than duplicated
- ~slacko-search~ takes an optional QUERY and routes to the Consult session where Consult is installed.  Consult and Embark stay optional: neither is a package dependency, and without them the command reads a query and fills an org buffer exactly as before
- Search results are displayed before their reactions are known, which is what used to hold a search up for one request per message
- The Makefile runs every Emacs against a repo-local sandbox, so a test run cannot write into the developer's own ~~/.emacs.d~

** Fixed
- Non-ASCII text in API responses arrived mangled: ~url~ hands the body back undecoded, and it is decoded as UTF-8 now

* [1.3.0] - 2026-07-02
** Fixed
- HTML entities in messages (~&amp;~, ~&lt;~, ~&gt;~) now decode to their literal characters instead of rendering raw; decoding runs as the last mrkdwn->org step so blockquotes, links, and double-encoded entities (~&amp;gt;~) stay correct
- ~slacko-emoji-mode~ auto-enables in search and thread buffers - the hook wiring previously sat behind ~with-eval-after-load~ forms that never fired because nothing loaded ~slacko-emoji~; the mode bodies now soft-require it, keeping ~emojify~ an optional dependency
- ~slacko-emoji--buffer-host~ is marked permanent-local: it is set before the major-mode call and ~kill-all-local-variables~ was wiping it, so workspace custom emojis never fetched on the first render

** Changed
- Credentials extraction reworked: workspaces are discovered from Slack's IndexedDB and a fresh ~api_token~ is fetched from each workspace's HTML page, replacing LevelDB token grepping and per-token ~auth.test~ identification; the Cookies DB is copied before querying so a running Slack app can't lock it

* [1.2.0] - 2026-02-20
** Added
- Custom workspace emoji support: emojis uploaded to a Slack workspace (e.g. ~:laughcry:~) now render as inline images instead of raw shortcodes
- ~emoji.list~ API integration to fetch all custom emojis per workspace, once per session
- Disk cache for downloaded emoji images under ~slacko-emoji-cache-directory~, avoiding repeated downloads
- Alias resolution for custom emojis that reference other emojis (recursive, depth-limited)
- Buffer-local ~slacko-emoji--buffer-host~ wired through search and thread buffers so the emoji resolver knows which workspace to query

** Fixed
- Auth-source cache clearing: ~slacko-creds--clear-cache~ now properly clears ~password-data~ (cons-cell keys) and ~auth-source-netrc-cache~ instead of operating on a nonexistent ~auth-source-cache~ variable
- Token authentication failure after Emacs restart: added ~(require 'url)~ and ~(require 'url-vars)~ to ~slacko-creds.el~ so that ~url-request-method~ and ~url-request-extra-headers~ are recognized as special (dynamic) variables under ~lexical-binding: t~

* [1.1.0] - 2026-02-19
** Added
- Interactive workspace selection with ~C-u slacko-search~ - when invoked with a prefix argument, prompts to choose from available Slack workspaces before searching
- ~slacko--available-hosts~ function to discover all workspaces from the credentials file, with auto-refresh when none found
- ~slacko--prompt-host~ for completing-read based workspace selection

* [1.0.0] - 2026-02-19
** Changed
- Renamed project from ~slack-search~ to ~slacko~ (a.k.a. "El Slacko")
- All symbol prefixes updated: ~slack-search-~ -> ~slacko-~, ~slack-mrkdwn-~ -> ~slacko-mrkdwn-~, ~slack-creds-~ -> ~slacko-creds-~, ~slack-thread-~ -> ~slacko-thread-~
- Main entry point is now ~slacko-search~ (was ~slack-search~)

** Added
- Inline image display in thread buffers - images are downloaded and rendered directly
- ~slacko-thread-inline-images~ and ~slacko-thread-image-max-width~ customization options
- Channel mention resolution: ~<#CHANNEL_ID|>~ now displays as clickable ~#channel-name~ links
- Strikethrough conversion: Slack's ~~text~~ now renders as org's ~+text+~
- Blockquote conversion: ~&gt; text~ renders with ~│~ prefix and custom faces
- ~slacko-mrkdwn-blockquote-face~ and ~slacko-mrkdwn-blockquote-bar-face~ for quote styling

** Fixed
- Match-data clobbering in user and channel mention resolution during API calls

* [0.1.0] - 2026-02-17
** Added
- slack-creds with functions to retrieve token from the registered slack app and keychain - Mac-only for now
- slack-thread for viewing individual threads and messages 

* [0.0.2] - 2025-01-20

** Added
- Major mode ~slack-search-mode~ derived from ~org-mode~ with custom keymap and hook support
- File attachments display with clickable links, human-readable sizes, and file types
- Support for shared messages from other channels with proper metadata display
- Shared messages show as subheadings with italicized metadata line including author, channel, and timestamp links

** Fixed
- Race condition that caused empty results on first search attempt
- Pagination logic to prevent auto-loading next page on initial search
- Buffer switching timing to ensure content is fully rendered before display
- Proper indentation using ~indent-region~ for all org-mode content
- Line break consistency: no blank line after heading, blank line before next entry, blank line before file list

** Changed
- Buffer formatting now uses proper org-mode structure with consistent spacing
- Shared message display uses subheadings (~**~) instead of quote blocks
- Error handling improved for HTTP response parsing with better user feedback

* [0.0.1] - 2025-10-18

** Added
- Initial release
- Basic Slack message search functionality
- Org-mode formatted results with clickable links
- Support for channels, DMs, group DMs, and private channels
- Slack mrkdwn to org-mode conversion (code blocks, inline code, links)
- Automatic pagination for search results
- Custom Slack link handler (~slack://~) with optional browser tab cleanup on macOS
